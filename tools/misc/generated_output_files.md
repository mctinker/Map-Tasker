# Generated Output Files

The files MapTasker writes, and what each one is for.  XML files are not listed.

'Current folder' is the folder MapTasker was started from.  'Settings folder' is the
one the operating system sets aside for this user's settings: `Library/Application
Support` on macOS, `APPDATA` on Windows, `XDG_CONFIG_HOME` or `.config` on Linux.

> Generated by `tools/misc/build_generated_files_doc.py` from the source.  Run it
> again rather than editing this page by hand.

## Views

The map and the diagram themselves, and what the 'Export' button writes.

| File | Written to | Produced by | What it holds |
| :--- | :--- | :--- | :--- |
| `MapTasker.html` | Current folder | Every run that displays the map | The mapping of your Tasker configuration.  It is opened in your default browser as a new tab. |
| `MapTasker_Diagram_Export.md/json/pdf` | Current folder | Diagram view > Export | The Diagram view exported as Markdown, JSON or PDF, one file per format. |
| `MapTasker_Map.txt` | Current folder | The Diagram view, or the '-outline' runtime option | A textual diagram of the configuration, displayed in your default text editor.  Turn text wrapping off and use a monospace font when viewing it, or the columns will not line up. |
| `MapTasker_Map_Export.md/json/pdf` | Current folder | Map view > Export | The Map view exported as Markdown, JSON or PDF, one file per format. |

## Reports

One per command that saves its results.  Each is stamped with the date and time it was written, so a run never overwrites the one before it.

| File | Written to | Produced by | What it holds |
| :--- | :--- | :--- | :--- |
| `MapTasker_Analysis_date_time.txt` | Current folder | 'Run (AI) Analysis' | The analysis the AI model returned for your configuration. |
| `MapTasker_Compare.txt` | Current folder | 'Compare Files' | What differs between two configurations. |
| `MapTasker_Find_date_time.txt` | Current folder | 'Find' > 'Save Results' | The saved results of a search. |
| `MapTasker_Fix_date_time.txt` | Current folder | 'Fix Findings' | What the repairs changed.  Kept apart from the Health Check report because that one says what is wrong and this one says what was done about it. |
| `MapTasker_Flowchart_date_time.txt` | Current folder | 'Task Flow' | The flowchart drawn for a single Task. |
| `MapTasker_HealthCheck_date_time.txt` | Current folder | 'Health Check' | What the check found wrong with the configuration. |
| `MapTasker_Refactor_date_time.txt` | Current folder | 'Refactor' | The preview a refactoring operation was applied from, or declined. |
| `MapTasker_Replace_date_time.txt` | Current folder | 'Find' > 'Replace' | The preview of a replacement: what would change, before anything does. |
| `MapTasker_TaskFlow_date_time.txt` | Current folder | 'Task Flow' | Every Task's If/Else/For/Goto structure, linted. |
| `MapTasker_Timeline_date_time.txt` | Current folder | 'Timeline' | What has changed in your own configuration since an earlier snapshot.  It is the comparison report under another name, so that 'what changed since Tuesday' does not land on top of a comparison of two separate files. |
| `MapTasker_VarXref_date_time.txt` | Current folder | 'Variables Xref' | Every variable, and everywhere it is set and read. |

## Settings and remembered state

What MapTasker carries from one run to the next.  Deleting any of these costs you the setting, not the configuration.

| File | Written to | Produced by | What it holds |
| :--- | :--- | :--- | :--- |
| `.maptasker.pkl` | Current folder | Older versions only | Where the AI API keys used to be kept.  It is no longer written; a leftover one is moved into the system password store and removed.  Hidden. |
| `.maptasker_changelog.txt` | Current folder | The version check | The change log fetched for a newer version, kept so it can be shown without fetching it again.  Hidden. |
| `.maptasker_last_run.txt` | Current folder | Every run | The date of the last run, so that a once-a-day check happens once a day.  Hidden. |
| `.MapTasker_RunCount.txt` | Current folder | Every run | How many times MapTasker has been run.  Hidden. |
| `.MapTasker_Settings.pkl` | Current folder | Older versions only | A second settings file that never held anything.  It is no longer written, and a leftover one is deleted unopened.  Hidden. |
| `MapTasker_API_Keys.json` | Settings folder | Saving an AI API key | Only written on a machine with no system password store.  Otherwise the keys go to the Keychain on macOS, Credential Manager on Windows, and GNOME Keyring or KWallet on Linux, and this file is never created. |
| `MapTasker_Apps.json` | Current folder | 'App not listed?' | The Application list fetched from the device, kept between runs and keyed by device.  Nothing is lost if you delete it; it is fetched again. |
| `MapTasker_Settings.toml` | Current folder | Every run | Your saved program settings.  You can edit it, but do not change a field's format -- an integer turned into a text string, say.  Incorrect values are ignored. |

## Folders

Written beside the files above, in the current folder.

| File | Written to | Produced by | What it holds |
| :--- | :--- | :--- | :--- |
| `MapTasker_Backups` | Current folder | Any save that would overwrite a file | A copy of a file taken just before a save would overwrite it, with only the ten newest kept per file.  Nothing is copied if there is nothing at the target path.  Old copies are removed for you, and you can delete single copies or the whole folder at any time without breaking anything -- it is recreated the next time a save needs it. |
| `MapTasker_Timeline` | Current folder | 'Timeline' | The history of your configuration, used to track what has changed.  The thirty most recent differing configurations are kept, each one compressed. |

## Diagnostics

Only written when something is being looked into.

| File | Written to | Produced by | What it holds |
| :--- | :--- | :--- | :--- |
| `.maptasker_error.txt` | Current folder | A failed parse | How a parse failed, written so the window that asked for it can report the error rather than lose it.  Hidden, and removed once it has been read. |
| `maptasker_debug.log` | Current folder | The '-debug' runtime option | A trace log for program debugging.  It is only created with '-debug', and a runtime error tells you to look here. |

## Tasker helper Tasks

Not files, but the other half of the Android story: each helper Task is added to
Tasker through the HTTP API the first time you use the feature that needs it, and
only if a Task of that name is not already there.  The 'vx' is a version, such as
'v2'.  They are what write the files in the Android table above.

| Task | What it does |
| :--- | :--- |
| `MapTasker Get Apps vx` | Gets the device's installed apps -- package, name, activity -- and matches each app name to its own package. |
| `MapTasker List Files vx` | Lists the files on the device.  It replaces the old 'MapTasker List' TaskerNet Profile. |
| `MapTasker List Tasker Objects vx` | Lists all Projects, Profiles, Scenes and Tasks in one run. |
| `MapTasker Backup For ID Check vx` | Runs Tasker's Data Backup so ids can be checked after an import.  The backup is only held in memory and is deleted from the device. |
| `MapTasker Import Profile vx` | Imports a staged Profile into Tasker's configuration. |
| `MapTasker Run Task vx` | Runs one of your Tasks by name and returns what it returned, passing %par1 and %par2 through.  'Run On Android' uses it for names Tasker's HTTP server cannot look up, such as '$Taskaroo'. |
| `MapTasker Open Tasker vx` | Opens Tasker, without handing it a file. |

Each import route has a pair, one that opens the file and one that sends an intent:
`MapTasker Open Profile vx` / `MapTasker Send Profile vx`, and the same for Project,
Scene and Task.
